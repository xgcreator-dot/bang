## 1. 产品概述

建设一套面向招投标信息服务的 Web 系统，由四个相互协作的平台组成：

1. **公开招标信息平台**：供访客和会员查询公开招标、采购意向、中标/成交结果等信息；项目详情对所有用户开放，与每条公告一一对应的准确原文详情 URL 为会员权益。
2. **会员管理平台**：供运营人员管理会员账号、会员等级、服务期限和服务记录。
3. **系统维护平台**：供系统管理员维护账号权限、基础配置、运行状态、告警和操作审计。
4. **大数据采集管理平台**：供数据人员维护公开信息来源、采集任务、数据清洗去重、质量审核和发布。

产品目标是形成“公开来源发现—采集与治理—信息发布—会员检索与服务—系统运营”的闭环。平台展示信息应能追溯至原始发布来源和原文链接。

## 2. 背景与问题

招投标信息由政府采购平台、公共资源交易平台、行业或企业采购网站等分散发布。用户需要跨网站查找、筛选并跟踪截止日期；运营团队需要管理会员服务；数据团队需要监控来源与采集质量；系统管理员需要维护账号、权限和系统运行。

本产品将这些职责放入统一系统，并按角色隔离入口和操作范围。采集对象限于可公开访问的信息；接入具体来源前需确认该来源允许的访问方式、频率及使用条件。

## 3. 产品目标与非目标

### 3.1 产品目标

- 用户可按关键词、地区、项目类型、公告类型、发布时间和截止时间筛选招投标信息。
- 每条信息展示来源平台、原文链接、发布时间和采集/更新时间，便于核验。
- 会员可以收藏项目、设置关注条件并接收匹配提醒（提醒渠道及服务范围待确认）。
- 运营人员可以查询和维护会员状态、等级、有效期和服务记录。
- 数据人员可以管理来源、执行/暂停采集任务、处理重复或异常记录并跟踪入库状态。
- 管理员可以配置角色权限、检查运行状态并审计关键操作。

### 3.2 本期不包含

- 代替招标人或采购人发布招标公告、组织投标或处理投标文件。
- 自动参与投标、自动联系采购方、提供中标保证或未经核验的商业评分。
- 绕过登录、验证码、访问控制、付费墙或来源平台明确设置的技术限制。
- 未经确认的移动 App、微信小程序、短信/邮件服务、支付和发票能力。
- 将采集内容作为平台原创信息发布；平台信息应保留来源与原文跳转。

## 4. 用户角色与权限

| 角色 | 主要职责 | 主要权限 |
|---|---|---|
| 访客 | 浏览公开招投标信息 | 搜索、筛选、查看完整项目详情；该项目准确原文详情链接需登录会员 |
| 注册会员 | 使用会员检索和跟踪功能 | 访客权限 + 访问来源原文链接、收藏、订阅、提醒、个人资料维护 |
| 运营人员 | 会员服务与日常运营 | 查看会员档案、调整经授权的会员状态/等级、记录服务事项 |
| 数据管理员 | 来源与数据质量管理 | 配置来源、管理采集任务、审核和纠错、查看采集日志 |
| 系统管理员 | 系统配置与安全维护 | 管理管理员账号、角色权限、配置、告警和审计日志 |
| 审计/只读人员 | 查看运营与系统记录 | 按授权范围查看，不得修改业务数据或配置 |

权限应采用最小授权原则；会员个人信息仅对履职所需人员开放，关键变更留审计记录。

## 6. 核心业务流程

### 6.1 信息采集与发布

1. 数据管理员登记来源名称、来源类型、官方入口、允许的获取方式、采集范围和访问频率要求。
2. 数据管理员创建采集任务，设定公告类别、地区范围、运行时间和失败处理方式。
3. 采集器按任务从公开来源获取页面或开放数据，保存来源标识、原文 URL、抓取时间及必要的原始响应证据。
4. 系统解析字段、标准化地区/金额/日期/类别，并生成重复候选和字段异常提示。
5. 可自动通过的记录进入待发布队列；低置信度、来源变更或关键字段异常的记录转人工审核。
6. 审核通过后发布到用户端；记录来源链接、原始发布时间、首次采集时间、最近更新时间和审核状态。
7. 任务失败、来源结构变化或异常率升高时生成告警，数据管理员处理后重跑或调整任务。

### 6.2 用户检索与会员使用

1. 用户进入信息列表，可直接搜索，也可组合使用筛选条件。
2. 任何用户打开详情均可查看平台收录的完整项目详细信息；详情页展示来源名称和原文链接入口。
3. 访客点击来源原文链接时，引导登录/注册会员；登录会员可直接跳转至发布方原始信息页面。
4. 登录会员可收藏项目、保存检索条件或订阅关键词/地区/类别。
5. 新匹配的信息按会员配置和系统规则生成提醒；提醒失败可追踪和重试。

### 6.3 会员服务

1. 运营人员搜索或筛选会员并查看档案、状态、等级、期限和服务记录。
2. 对经授权的变更进行确认，填写原因；系统记录操作人、时间、变更前后值。
3. 到期提醒和状态规则按确认后的会员政策执行。

### 6.4 系统维护

1. 管理员查看运行服务、任务队列、告警和最近操作。
2. 管理员按角色管理后台访问权限；高风险变更需要二次确认或双人复核（是否启用待确认）。
3. 系统记录登录、权限修改、会员关键变更、来源/任务配置和数据审核等操作。

### 8.1 招投标信息

| source_url_status / checked_at | 原文链接状态（待校验、有效、失效、目标不匹配）及最近校验时间 | 是 |
| collected_at / updated_at | 首次采集时间/最近更新同步时间 | 是 |
| status | 待审核、已发布、已撤回、待核实等 | 是 |
| content_hash / version | 内容版本识别与更正追踪 | 是 |

### 8.2 会员

会员编号、个人/企业类型、姓名/企业名称、手机号或登录标识、联系方式验证状态、会员等级、状态、注册时间、服务开始/到期时间、协议/同意记录、收藏和订阅关系、操作审计记录。敏感字段按最小化原则收集并进行访问控制。

### 8.3 来源与采集任务

来源目录与任务配置分离。来源目录记录来源身份和规则，任务引用来源并定义采集范围/调度；任务运行记录独立保存每次执行结果，原始采集记录与标准化业务信息分别保存以便核验和重处理。

## 9. 搜索与信息质量规则

- 搜索须支持中文标题、采购单位等字段检索；分词、同义词和拼写容错策略由技术方案确定。
- 默认只展示审核通过且未撤回的信息；更正公告与原公告应建立关联。
- 金额字段同时保留源文原始表达和标准化数值，不得在无法解析时猜测。
- 时间统一存储并明确时区；用户界面按中国标准时间显示。
- 来源原文链接作为事实核验入口；若信息解析与原文冲突，应以来源原文为准并允许用户反馈纠错。
- 采集器必须从来源公告列表/详情中取得当前公告对应的详情链接，并将其与该条标准化公告记录绑定；不得只保存来源平台首页、栏目页或检索结果页作为原文链接。
- 入库前校验原文 URL 为允许来源域名下的 HTTP(S) 地址，并核对目标页面与记录的公告编号、标题或其他稳定标识；校验未通过的记录进入待核验队列，不对用户开放错误直达链接。
- 链接校验应区分“目标项目不匹配”和“暂时无法访问”。对暂时无法访问的链接可按策略重试；确认失效后标记并提示，不自动改跳首页。来源域名变更需经数据管理员审核。
- 前端详情页的会员直达动作只能读取该条记录存储的 `source_url`。服务端对目标域名执行 allowlist 校验，避免开放重定向；无有效 `source_url` 时返回不可用状态。
- 对相同项目多来源转载建立来源关系，保留各个原文链接和发布时间。
- 采集质量指标定义需固定口径：成功率、有效记录率、重复率、字段完整率分别按任务运行与来源维度统计。

## 10. 非功能需求

### 10.1 安全与隐私

- 全站 HTTPS；密码采用强哈希存储，不以明文保存或展示。
- 后台角色权限服务端校验，前端隐藏入口不构成权限控制。
- 会员个人信息传输和存储采取访问控制、日志审计及必要的脱敏措施。
- 管理员登录、会员状态/等级变更、导出、权限变更、采集配置和审核操作均留痕。
- 设定登录保护、会话过期、异常登录检测、备份和恢复策略。
- 明确个人信息收集目的、必要字段、保存期限、删除/注销流程及用户告知同意方式。

### 10.2 性能与容量（目标值，待结合预算确认）

- 常见搜索请求在正常负载下 P95 响应时间不超过 2 秒。
- 列表分页加载在正常负载下 P95 不超过 2 秒。
- 采集任务不得影响面向用户的在线查询；采集与检索资源隔离或限流。
- 系统容量按来源数、日采集量、保留周期和并发用户数进行容量规划，正式指标在技术设计阶段确认。

### 10.3 可用性与兼容性

- 用户端支持桌面和移动浏览器自适应布局。
- 失败任务具备可观测错误、有限重试和人工重跑方式。
- 关键数据定期备份；恢复目标（RPO/RTO）需在上线前由业务与运维确认。
- 页面明确空状态、加载状态、无权限、数据更新时间和错误提示。

## 11. 指标与埋点

### 产品指标

- 收藏量及收藏项目后续详情访问情况。

### 数据指标

- 每来源采集成功率、有效信息量、字段完整率、重复率、审核退回率、发布延迟。
- 来源失联时间、结构变更发现时间、异常处理时长。

### 运维指标

- 核心服务可用率、接口 P95 响应时间、告警响应/恢复时长、后台高风险操作数量。

## 13. 验收标准（MVP）

1. 用户可组合使用关键词、地区、类型和公告类别筛选结果，并能清空条件、分页和打开完整项目详情。
2. 未登录访客可查看完整项目详情；详情页来源原文入口要求登录会员。
3. 会员登录后点击来源原文入口必须直接跳转至该项目对应的准确公告详情 URL（deep link），不得跳转来源平台首页、搜索页或其他公告；缺少或无法验证准确 URL 时应禁用入口并提示链接暂不可用。
4. 已发布信息具有来源名称、来源发布时间（如源站提供）和平台采集/更新时间；准确原文详情 URL 未采集到时不显示可跳转链接。
5. 运营人员可按关键字段找到会员并完成授权范围内的新增、编辑、停用操作，所有关键变更可审计。
6. 管理员可配置并查看角色权限，越权请求由服务端拒绝并记录。
7. 数据管理员可建任务、暂停/恢复任务、查看每次运行结果，并定位失败原因。
8. 采集记录支持标准化、重复候选提示、审核和发布/退回；已发布记录可追溯到来源和采集批次。
9. 来源或采集任务未配置必要的访问规则/频率上限时，不可启动正式采集。
10. 对每条公告执行链接验收：点击会员入口后最终打开的页面对应同一公告编号或标题；缺失 URL、平台首页、栏目页、搜索页、其他公告页均判定不通过。
11. 无法匹配到准确公告详情页或链接校验失败时，系统不得用来源首页兜底；记录需进入待核验状态，前端显示链接暂不可用。
12. 移动与桌面端主要流程可用；表单错误、无结果、无权限和任务失败均有明确状态提示。

## 14. 风险与依赖

- **来源接入条件**：每个来源的获取方式、访问频率和内容使用条件需逐一核实；来源规则变更可能导致任务暂停。
- **数据准确性**：公告字段复杂且可能更正/撤回，需保留原文、版本与人工纠错路径。
- **重复转载**：多平台转载和同项目分阶段公告增加关联判断难度，需允许人工确认。
- **会员权益边界**：免费/付费差异、搜索额度、提醒频率和导出权限尚未定义。
- **个人信息保护**：账号、联系方式和运营记录需要确定最小收集范围、保存期限和授权策略。
- **系统容量与成本**：来源数量、日采集规模、搜索并发量和历史保留周期尚未提供，影响存储、搜索引擎和调度方案。
- **通知渠道**：短信、邮件、站内消息或企业微信等渠道需要相应服务商、预算与用户同意策略。

## 附录 C：智能采集平台目标与来源接入策略

### C.1 目标定义

“全网所有公开招标信息”不是一个可客观保证的完整性承诺：公开信息分布在全国、地方、行业及企业平台，各自接口、发布范围和更新时间不同；部分信息未接入统一汇总平台，部分来源也没有可供第三方直接使用的公开接口。因此系统目标定义为：

> 在明确的地域、信息类别、来源清单及接入规则范围内，持续发现可合法接入的权威公开来源，自动采集、解析、去重和跟踪更正信息；提供可量化的覆盖率、延迟和缺口，不宣称无边界的“全网全量”。

首期默认地域为中国大陆，首期数据类型包括依法公开的招标公告、资格预审公告、中标候选人公示、中标结果公示、更正/延期公告及采购意向。政府采购、工程建设、公共资源交易、央国企采购等来源分开统计覆盖，不以一家聚合平台代表所有企业采购信息。

### C.2 权威来源接入优先级

| 层级 | 接入方式 | 使用原则 |
|---|---|---|
| L1 | 官方开放数据接口、正式数据服务、官方授权数据交换 | 首选。按官方规范签名、鉴权、版本、数据字典、调用频率及用途要求接入；需要申请账号或授权时，完成申请后再启用 |
| L2 | 官方 RSS/Atom、开放下载文件、公开数据目录 | 解析公告条目及其项目详情链接；保留来源标识与原文 URL，遵循来源说明和更新机制 |
| L3 | 官方公开网页 | 仅在来源访问规则允许、页面无需登录且不存在访问限制时采集；使用低频、增量、可暂停的适配器 |
L4 | 经确认的省级、行业、央国企或交易平台公开来源 | 逐站记录主体、授权/规则依据、内容范围和联系人；每站独立适配与评估 |

来源按官方性、信息覆盖、URL 完整性、更新延迟、数据质量和可接入性评分，作为接入和运维优先级依据；评分不能代替法律审核或来源授权。

### C.3 智能发现与治理流程

1. **来源发现**：定期同步已知官方平台提供的发布媒介/平台目录；结合已登记来源发现的新发布平台、来源域名变更和链接跳转，生成“待核验来源”，不得直接对新域名无审核启动高频采集。
2. **来源准入**：保存来源主体、官方入口、支持的数据类别、地域、允许的接入方式、访问频率、规则/授权凭据、数据保留条件、最近复核时间及负责人。缺少必要接入依据时保持暂停。
3. **连接器选择**：根据来源能力优先选择正式 API/数据服务，其次 RSS/Atom/下载文件，再采用合规的公开页面适配器。每种方式使用独立连接器，不能用单一通用爬虫假定所有网站结构一致。
4. **自适应调度**：根据来源公告更新频率、历史成功率和流量限制调整轮询间隔；连续失败、频率限制、结构变化、挑战页或异常跳转时自动退避/暂停并告警，不尝试绕过验证码、登录、付费墙、访问控制或反爬限制。
5. **智能解析**：解析 HTML、结构化数据和经许可处理的 PDF 公告；按标准字段提取。每个字段保存原文证据片段、来源位置和置信度；低置信度字段、金额/截止日期冲突、项目身份不确定时进入人工审核，不凭模型补造事实。
6. **实体关联与更新**：用来源公告编号、项目编号、准确原文 URL 和标题/采购人等字段去重；把招标、澄清、更正、延期、候选人公示和结果公告串成项目时间线。重复转载保留多个来源链接，不覆盖原始版本。
7. **覆盖监控**：提供按省份、信息类别、来源、行业的已覆盖/待接入/暂停/缺失状态，显示最近采集时间、同步延迟、失败率、链接有效率、重复率、字段完整率和来源缺口。覆盖率分母采用已确认的官方来源目录或明确的业务清单，并在界面说明统计口径。
8. **反馈闭环**：用户报告失效链接或错误信息后生成核验项；核验结果可修正当前记录，同时保留来源版本、修正人、时间和证据。

### C.4 智能解析字段与证据

对项目标题、公告类型、招标人/采购人、代理机构、地区、行业、预算金额、投标截止时间、开标时间、项目编号、资格条件、公告原文 URL 等字段，记录：标准化值、原文值、证据片段、解析方式（接口字段/规则/模型/人工）、置信度、更新时间和审核状态。项目直达 URL 必须来自来源记录本身，不得由 AI 推测或拼接。

联系方式等可能识别自然人的信息默认不进入用户端结构化字段；若业务确有必要处理，应先确认目的、必要性、合法依据、范围及保护措施。公开可见不自动等于可无限制收集、长期保存或再次公开。

### C.5 来源边界与合规控制

- 仅采集已登记且有明确接入路径的公开信息；来源授权、服务条款、robots 规则、接口规范和频率要求由数据管理员在每个连接器启用前核验并记录。
- 禁止绕过登录、验证码、访问控制、付费墙、签名鉴权或反爬技术；遇到来源拒绝、限制或规则不明即暂停并人工核查。
- 公开页面只采集业务所需的最小字段；附件下载、全文存储、对外展示和长期留存分别按来源规则审查。
- 原文 URL、采集批次、来源版本、采集/更新时间和处理记录可追溯；发布内容仍应注明来源并提供会员直达原公告链接。
- 覆盖范围公开展示口径与限制，不使用“全网100%覆盖”或无法验证的完整性宣传。

### C.6 首批来源建议与依赖

1. **中国招标投标公共服务平台及省级发布媒介目录**：依据国家发展改革委《招标公告和公示信息发布管理办法》，国家平台承担全国信息汇总及与省级发布媒介、公共资源交易平台的信息共享职责；应优先核验其可供本平台使用的正式查询/数据接入方式，并把省级、行业、交易平台目录纳入来源发现种子。
2. **中国政府采购网及地方分网**：遵循官网当前版本《中国政府采购网数据接口规范》和申请流程。官网通知说明接口调试地址、账号和验证方式会向获批对接单位提供；该规范不是可假设匿名开放的第三方抓取 API。未获得使用资格时，另行评估允许的公开查询入口。
3. **全国公共资源交易平台/数据服务**：优先核验数据服务可提供的数据类别、时间范围、查询能力、条款和接口权限；平台展示的数据覆盖范围不能直接等同于其提供无限制批量接口。
4. **省级公共资源交易平台、行业和央国企采购平台**：按目录逐站登记，确认与国家/省级平台的重复关系和独有信息类别，按正式接口、Feed 或经审核页面适配器分批接入。

正式排期依赖来源方对接口文档、授权/账号、配额和数据使用方式的确认。对方未提供访问权限时，系统不会以猜测接口或规避限制来填补覆盖缺口。

### C.7 智能采集验收指标

- 每个来源都有准入状态、接入方式、来源 URL 域名、访问频率、负责人、最近复核和适用规则记录。
- 自动发现的新来源先进入待核验清单；未获准来源不会被调度。
- 公告标题、源站公告标识、项目详情 URL 和来源发布时间均保留来源证据；项目详情 URL 不允许模型生成。
- 对同一来源重跑能更新已有公告而不重复创建；更正/延期/撤回形成可追溯版本和项目关联。
- 结构变更、异常跳转、挑战页面、连续失败和频率限制会触发退避/暂停与告警，不触发绕过机制。
- 解析模型输出带字段级置信度与证据；低置信字段不自动发布。
- 运营看板能按省份、信息类别和来源显示已知目录覆盖状态、更新时间及缺口，并展示统计分母。
